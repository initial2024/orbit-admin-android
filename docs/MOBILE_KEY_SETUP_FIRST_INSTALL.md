# Orbit Mail · Android phone signing key setup checklist

> **Current state:** A protected signing workflow is in Git, but **that is
> not evidence that GitHub Production contains the user's real private key**.
> Never upload signing material to repo Contents, a PR, a Release, a chat or
> AVENQIR admin. No official v0.9.30 APK exists until actual signed release.

## Distinguish the three credentials

| Credential | Where created | Used for | Never share |
| --- | --- | --- | --- |
| AVENQIR admin `adm` TOTP | HTTPS `admin.php` after current-password verified | 6-digit verification for AVENQIR directory admin | TOTP QR/secret, recovery codes |
| AL Sandbox VNC password + Cloudflare Tunnel token | `al_private_browser.sh password` and Cloudflare Dashboard | Owner-only remote Chrome access | VNC password, Tunnel connector token |
| **Orbit signing keystore (PKCS12)** | Android phone/secure offline owner storage, one time | All future Orbit stable APK updates | `.p12`, base64 key, store/key passwords |

**AL check scripts do not ask for any of these.** Read-only status reports
are not installations, and web-admin TOTP is not Android APK signing.

## 1. Check for a previous stable key FIRST

Open [the GitHub Production environment](https://github.com/initial2024/orbit-admin-android/settings/environments)
on the repository owner's account. If an existing stable keystore has
already been backed up and configured, **reuse it**. Never create a
replacement simply because you cannot read GitHub's Secrets values.

Required **Production secrets**:
- `ORBIT_RELEASE_KEYSTORE_BASE64` (encrypted PKCS12 keystore, base64)
- `ORBIT_RELEASE_KEYSTORE_PASSWORD`
- `ORBIT_RELEASE_KEY_ALIAS`
- `ORBIT_RELEASE_KEY_PASSWORD`

Required **Production variable**:
- `ORBIT_RELEASE_CERT_SHA256` (64 hex characters of **certificate SHA-256**,
  not a SHA-256 of the `.p12` file)

Values of GitHub Secrets cannot be read back after upload. Use the
one-click, protected [**Orbit signing key readiness (no APK published)**](https://github.com/initial2024/orbit-admin-android/actions/workflows/orbit-signing-key-readiness.yml)
workflow **on main** to prove the secret set is usable; it checks the
private key and cert pin while printing no secret material.

If the readiness result is `SIGNING_KEY_READINESS=PASS`, **do not recreate
your key**. If it reports a missing item, set that item privately using
the directions below. This check never creates a new signing key or APK.

## 2. Only if the original keystore truly does not exist

On a trusted Android device install Termux from an official channel.
Use [the detailed owner-only one-time signing guide on the Android release
candidate](https://github.com/initial2024/orbit-admin-android/blob/release-candidate/orbit-avenqir-v0.9.30-20261123/docs/ORBIT_FIXED_SIGNING_FROM_ANDROID.md).
It gives the exact `keytool` / `gh secret set --env Production`
commands, without writing passwords into shell history or GitHub commits.

Important checkpoints:
1. Generate encrypted PKCS12 **once** under Termux only if none exists,
   with long random password and the documented alias.
2. Export **two independently stored private backups** of the encrypted
   keystore before relying on the GitHub encrypted copy for future updates.
3. Use your own authenticated `gh auth login` on the phone to upload its
   base64 as a **GitHub Environment Secret**, then enter the two password
   secrets interactively. **Do not paste the key into this conversation.**
4. Pin the certificate fingerprint generated by `keytool -list -v` in
   the **Production variable**, not in the app source tree.
5. Trigger the protected readiness workflow and confirm PASS.

No previously installed Orbit Mail APK is present on the phone per
the owner's latest report, so this release is a **first installation**:
comparing the signer to a non-existent installed APK is N/A. Nevertheless,
the stable key and pin must be retained for *future* in-place updates.

## 3. Separate production-release authorization

**Key readiness PASS is necessary but insufficient to publish APK.**
The reviewed Android app source and version 0.9.30 must first enter
`main` (PR #5 remains Draft), production-dependent endpoints must be
approved, and a real Vivo device must pass login/2FA, AVENQIR, file
handling, and return-from-background acceptance. Then the operator may
manually run the **Orbit Mail stable signed APK (protected manual)**
workflow on `main` with the exact acknowledgement `PUBLISH_SIGNED_STABLE`.
This job produces a real GitHub Release APK, ZIP, certificate pin and SHA-256.

Stop on any signer mismatch, key loss, untrusted browser request for a
keystore, or failed Production approval. Unsigned or debug artifact
success does **not** count as an official stable APK.
